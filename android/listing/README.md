# Google Play listing

Everything the Play Console asks for that lives in the repository, so a
listing can be assembled from a checkout. Nothing here is submitted
automatically: a person pastes these texts and uploads these files.

## Files

| Console field | Source |
| --- | --- |
| App name | `Aether` |
| Short description (80 characters max) | [short-description.txt](short-description.txt) |
| Full description (4000 characters max) | [full-description.txt](full-description.txt) |
| App icon, 512x512 32-bit PNG | [`web/public/icons/icon-maskable-512.png`](../../web/public/icons/icon-maskable-512.png) - full-bleed, because Play applies its own mask |
| Feature graphic, 1024x500 PNG with no alpha | [feature-graphic.png](feature-graphic.png), regenerated by `python3 scripts/make-icons.py` |
| Phone screenshots | Taken on a real phone; see below |
| Privacy policy URL | <https://github.com/3xDevOps/Aether/blob/main/docs/privacy.md> ([docs/privacy.md](../../docs/privacy.md)) |
| App access | [app-access.md](app-access.md) |
| Data safety | [data-safety.md](data-safety.md) |
| Category | Productivity |
| Contact email | The publisher's support address; not in the repository |
| Release file | `aether-android.aab` from the GitHub release, [docs/install.md](../../docs/install.md#releases) |

Play's asset rules are at
<https://support.google.com/googleplay/android-developer/answer/9866151>.

## Screenshots

Play wants between two and eight phone screenshots, JPEG or 24-bit PNG
without alpha, each side between 320 and 3840 pixels and no side more than
twice the other. For the listing to be promoted, at least four at 1080x1920
or larger. Take them on a phone signed in to a tailnet with a running server,
in this order, so the listing reads as a tour:

1. The board, with a few runs in different buckets.
2. A run's terminal with the key bar showing.
3. The approval inbox with a pending request.
4. A run's diff.
5. The first screen, **Aether server**, empty.

Tablet screenshots are optional and the app declares no tablet-specific
layout; skip them.

## Signing

The release keystore signs both the APK on the GitHub release and the bundle
Play takes. On Play it is the **upload key**: Play App Signing re-signs what it
serves with an app signing key of its own, so an install from Play and an
install of the GitHub APK are different apps to Android and never update each
other. Enrolling with the existing key as the app signing key would make them
one lineage, at the cost of handing that key to Google. Decide on the first
Play release; it cannot be changed afterwards
(<https://support.google.com/googleplay/android-developer/answer/9842756>).
